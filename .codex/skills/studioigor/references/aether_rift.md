# Профиль проекта «Разлом Эфира»

Корень проекта — `D:\проект 1`. Перед работой прочитай `AGENTS.md` в этом корне и `.studioigor/STATE.md`. Технические стандарты проекта и этот профиль имеют приоритет над общим процессом ниже и примерами в `references/`.

- Концепт и стек утверждены. Используй Windows, Godot 4.7.2, типизированный GDScript, `godot-mcp` и установленный Phantom Camera. Текущая работа начинается с фазы 6. Пользователь выбирает момент первого игрового прогона.
- Для продолжения смотри `.studioigor/STATE.md`, `DESIGN.md` и `DECISIONS.md`. Команда из корня проекта — `py -X utf8 .codex/skills/studioigor/scripts/studio.py status --no-run`. Для запуска команд на Windows используй PowerShell и существующие инструменты Codex.
- Перед каждым залом прочитай [методику механик](mechanics.md) и [стандарты кода](code.md). Для изменения `.tscn` сначала проверь проект через `godot-mcp`. После изменения запусти конкретную сцену в отладке и проверь `get_debug_output`.
- Один зал изолирует одну механику или тесно связанный цикл. Сцены размещай в `res://src/world/gyms/`, игровую логику в подходящих модулях `src/`, параметры в `res://src/resources/`, панель в `res://src/ui/`. Панель управляет тем же экземпляром `Resource`, который читает игра. Зал запускается напрямую.
- Первый цикл — бег, рывок и прицеливание из лука с замедлением времени. `Tab` открывает панель, `R` возвращает на старт, `P` сохраняет снимок значений в `user://gym_tuning/`, `O` показывает метрики. Обновляй значения по умолчанию после плейтеста и согласования.
- Храни проверки и решения в `.studioigor/`. Запиши отзыв пользователя в `PLAYTESTS.md` его словами, внеси одну группу изменений за итерацию и помечай механику `locked` после утверждения. При наличии Git изолируй изменения и делай узкие коммиты согласно правилам проекта.
